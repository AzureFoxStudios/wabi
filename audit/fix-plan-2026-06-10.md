## 1. Login Logo CSS Conflict (DONE)

### Problem
`login.css` defined a global `.logo` class that conflicted with the sidebar's `.logo` class. Because login CSS is imported globally (not scoped), it was overriding the sidebar logo sizing, making the in-app server logo tiny.

### Fix Applied
- **File:** `frontend/src/lib/components/Login.svelte`
  - Renamed class `logo` → `login-logo`
  - Renamed class `logo-compact` → `login-logo-compact`
- **File:** `frontend/src/lib/components/login.css`
  - All `.logo` selectors → `.login-logo`
  - All `.logo.logo-compact` selectors → `.login-logo.login-logo-compact`
- **Result:** Login logo is now properly scoped; sidebar logo is unaffected.

## 2. Mock User Role: Guest Sees Admin (DONE)

### Problem
In local mock mode (`localMockSocket.ts`), the mock user's `highestRole` was set to `'owner'`, which meant every developer/testing session saw the Admin tab in Settings and could access all admin functionality. This masked the real guest experience.

### Fix Applied
- **File:** `frontend/src/lib/localMockSocket.ts`
  - Changed `highestRole: 'owner'` → `highestRole: 'guest'`
  - Added `admin` and `mod` role definitions to `_setRoleDefinitions()` so the role system is populated correctly even as a guest
- **Result:** Mock users start as guests, correctly hiding admin content. Admin panel is only visible when explicitly testing with owner/admin role.

## 5. Message Hover Quick Buttons (DONE)

### Problem
The message action buttons (reply, react, more) that appear on hover over a message had "poofed" — they weren't visible. This was a combination of positioning, z-index, and animation issues.

### Fix Applied
- **File:** `frontend/src/styles/components/ml-actions.css`
  - Position: adjusted from `top: -10px; right: 0px` to `top: -8px; right: 12px`
  - z-index: 10 → 80 (was hidden behind other elements)
  - Animation: added `scale(0.98)` initial state for subtle pop-in
  - Visibility trigger: added `.message:focus-within` and `.message-actions.mobile-visible` as additional show triggers
- **File:** `frontend/src/styles/components/ml-core.css`
  - `.message` added `overflow: visible` so action buttons aren't clipped
- **Result:** Message actions reappear on hover with smooth animation.

## 9. Whiteboard Canvas CSS Missing

### Problem
`WhiteboardCanvas.svelte` imports `./WhiteboardCanvas.css` on line 14:
```ts
import './WhiteboardCanvas.css';
```
But this file does **NOT exist** on disk. The `glob` search for `**/whiteboard*.css` returned no results, and `**/WhiteboardCanvas.css` also returned nothing. This means the whiteboard canvas has zero styling — all its class names are unmatched, causing the canvas, import HUD, text overlay, etc. to render without any layout or appearance styles. This is why the user says "WHOA whiteboard got DEMOLISHED!".

### Plan
Create `frontend/src/lib/components/WhiteboardCanvas.css` with styles for all the classes used in `WhiteboardCanvas.svelte`:

**Classes used in the template:**
- `.whiteboard-canvas-container` — main container, needs to fill space, position relative, overflow hidden
- `.whiteboard-layer` — shared canvas styles (absolute positioning, full size)
- `.base-layer` — z-index: 0
- `.interaction-layer` — z-index: 1
- `.text-edit-overlay` — textarea for text tool, needs absolute positioning, transparent bg
- `.whiteboard-import-hud` — container for import overlay/queue
- `.whiteboard-import-overlay` — drop zone overlay during drag
- `.whiteboard-import-overlay.is-error` — error state
- `.whiteboard-import-queue` — queue of pending import cards
- `.whiteboard-import-card` — individual import card
- `.whiteboard-import-card.is-active` — currently uploading card
- `.whiteboard-import-thumb` — thumbnail image
- `.whiteboard-import-thumb--empty` — empty thumbnail placeholder
- `.whiteboard-import-copy` — text info column
- `.whiteboard-import-name` — file name
- `.whiteboard-import-meta` — source + status
- `.whiteboard-import-more` — "+N more queued" pill

**Design decisions:**
- Match existing whiteboard aesthetic (WhiteboardTab svelte styles use light backgrounds, blur, rounded corners)
- Container should fill the `.whiteboard-surface` parent (which is set to `height: 100%` in Chat.svelte)
- Canvas layers stack on top of each other
- Import HUD overlays at bottom-left or center
- Text overlay should have minimal styling (transparent bg, visible caret)

**File to create:**
- `frontend/src/lib/components/WhiteboardCanvas.css` — new file, ~120 lines
