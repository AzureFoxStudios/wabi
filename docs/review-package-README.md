## The questions that matter for review

1. **Is the design sound?** Every architectural choice in `wabidb-endstate.md` is derived either from STDB patterns that work (and we kept) or from a deliberate "Wabi is not that" boundary (and we replaced). The Wabi-specific extensions (addon object primitive, helper-node protocol, range-read blob store, two-tier data lifecycle) are all there with rationale.

2. **Is the boundary correct?** Section 13 of `wabidb-endstate.md` lists what WabiDB is NOT. If a reviewer thinks a boundary should be different (e.g., "WabiDB should be a real SQL database" or "WabiDB should support federation"), that's a fundamental redesign, not a tweak.

3. **Is the data model grounded in the actual frontend?** Section 12.4 of `wabidb-endstate.md` has a "Feature Preservation" table mapping each real frontend file to the corresponding WabiDB table. Cross-reference the actual files in `frontend/src/lib/` and `frontend/src/lib/components/` to verify coverage.

4. **Is the addon system actually flexible enough?** Section 9.9 introduces the addon object primitive. The CAD-as-addon worked example shows how a complex feature fits without bloating the engine. If a reviewer has a different "complex feature" in mind (music sequencer, video editor, etc.), apply the same pattern and see if it holds.

5. **Is the migration path realistic?** Section 12.5 is brief — the full migration plan is NOT yet written. This is the one real follow-up item flagged in the research. The blocker is STDB's data export (no clean dump tool exists; the migration has to read STDB while it's still live and transform).

## What converged across three independent research passes

- SQLite WAL handles Wabi's expected scale (1k-10k users) easily with proven PRAGMAs
- Tokio + tokio-tungstenite scales to 100k+ WebSocket connections; 1k is trivial
- Per-recipient DM encryption (Signal's Sesame pattern) has negligible storage cost
- BLAKE3 is overkill in the right way (3-15 GB/s)
- Figma's production architecture validates the in-memory-hot + durable-committed + WAL pattern
- JWT/PASETO/Macaroons are all valid for the helper-node signed-token approach
- The frontend's data shapes are covered field-by-field in the WabiDB schema

The single MEDIUM risk item: STDB data export for the migration.
