# Regional upload cache for an Anchor

**Status:** Opt-in working-tree candidate for reducing repeat attachment bytes over the Authority uplink. It is not a standby, a replacement for the Authority, or a completed three-site field result.

Set `WABI_ANCHOR_UPLOAD_CACHE_MB=64` on an Anchor to set a 64 MiB budget for retained upload copies. Zero or an unset value disables the cache. Values above 1024 MiB are refused. Up to eight cache fills may temporarily hold another 8 MiB each, and active responses can keep evicted bytes alive until delivery finishes; size host memory above the configured cache budget. A single cached file is limited to 8 MiB; large downloads still stream from the Authority. The Anchor only considers simple `GET /uploads/{filename}` requests with no query, range, or conditional header. Eligible files need a canonical `upload_published_v1` size and SHA-256 record; older registered files can enter that path through the [offline backfill](LEGACY_UPLOAD_BACKFILL.md). Other API and media routes continue through their existing paths.

For each eligible request, the Anchor forwards a HEAD check with the client's auth headers to the Authority. The current `/uploads/` route checks the file URL and revocation, rather than a per-member file ACL; forwarding auth does not turn it into a member-only route. Operators must treat a known upload URL as sufficient to request the file. A cache miss fetches the file once, verifies its bytes against the Authority's canonical digest, and stores it in bounded memory. A hit serves local bytes only after the Authority again confirms the same digest, availability and an unqualified `no-cache` policy. A missing policy or any `no-store` directive evicts the entry and forwards the GET. A denial, revocation, changed digest, changed cache policy, or unavailable Authority prevents a cached hit. The response header `X-Wabi-Anchor-Cache` reports `miss` or `hit` for field measurements. Two Anchors have separate caches; placing them on separate useful uplinks is what can reduce inter-site file traffic.

The Authority now returns a cheap HEAD response and a digest validator for canonical uploads. Canonical uploads use `Cache-Control: private, no-cache` so browser copies must revalidate; legacy and authenticated whiteboard files use `private, no-store`. A client's `Cache-Control: no-store` request bypasses the Anchor cache, including mixed-case or repeated header forms. The service worker fetches revocable upload and whiteboard files from the network without a stale offline fallback, and an updated worker removes its older media cache. This can make those files unavailable during an outage. A browser or other client that already saved bytes, a remote cache, a swap file, or a backup cannot be remotely erased by a revocation.

**Capacity and privacy limits:** A hit still costs one Authority HEAD request, so this reduces origin *bytes* rather than eliminating origin request load. It does not make the file available when the Authority is down. Revocation can occur in the short interval after a successful HEAD check and before delivery; the field privacy gate must measure and define that race. Measure Authority and Anchor egress, hit rate, validation latency, rejected requests, and memory use at all three sites before treating this as a bandwidth result. Cache entries are process-local and disappear on restart; operators should protect the Anchor host's memory and crash dumps because it temporarily holds private capability-URL content.

The [geographic community plan](../plans/2026-09-26-geographic-community-nodes.md) still requires the three independent networks, fallback behavior, and later state/failover gates.

A [disposable real-process preflight](../testing/THREE_SITE_REAL_AUTHORITY_PREFLIGHT_2026-09-27.md) starts one Authority and two Anchors on loopback, sends a resumable upload through one Anchor and checks cache miss/hit through the other. It now meters the equipment Anchor's upstream TCP bytes for both downloads. Operators can reproduce it with `node scripts/three-site-real-authority-smoke.mjs target/debug/wabi-server` after building the binary. Run the separate three-network scenario before attributing a bandwidth improvement to geographic placement.

A later [three-computer Tailscale run](../testing/THREE_SITE_FIELD_2026-09-27.md#follow-up-byte-metered-three-computer-run) measured 263,175 Authority-to-equipment-Anchor TCP bytes on a 262,144-byte file miss and 504 bytes on the repeat hit, with a fresh HEAD check. Both sampled embedded app-asset requests caused zero upstream bytes. The meter covers these controlled Anchor paths rather than whole-interface egress or sustained hit rate. A fresh egress check also found iRonin and Iyoku on the same public IPv4 egress and local LAN path, so this does not yet verify three independent sites.

After iRonin moved, a [fresh three-site run](../testing/THREE_SITE_FIELD_2026-09-28.md)
qualified three distinct uplinks and repeated the same miss/hit and local-asset
measurements. It also checked HTTP and authenticated Socket.IO clients running
on Ronin and Iyoku. This advances physical access and scoped byte offload;
whole-uplink traffic, sustained hit rates, media, privacy races and full desktop
acceptance still need measurement. Cached files continued to return 503 after
Authority shutdown.
