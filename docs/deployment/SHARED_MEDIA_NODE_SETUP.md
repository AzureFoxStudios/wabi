# Shared Wabi Media Node Setup

**Status:** early implementation / operator testing  
**Updated:** 2026-09-14

A shared Wabi Media Node lets one publicly reachable SFU serve several completely
independent Wabi Authorities. This is infrastructure sharing, not federation.
The Authorities keep their own users, permissions, channels and databases.

The current controller is `scripts/wabi-media-node.py`. It has no third-party
Python dependencies and is intentionally separate from the generic Wabi helper
runtime while the multi-tenant media contract is being certified.

## What you need

- a publicly reachable SFU endpoint (Wabi 1.x target: self-hosted LiveKit);
- Python 3;
- one MediaRelay pairing token generated by **each** Wabi Authority that may use
  this node.

The SFU may be on the same public machine as the controller. The Wabi Authorities
do not need public UDP and may remain behind NAT/CGNAT as long as the controller
can reach their HTTPS API.

## 1. Create the config

Copy the example:

```bash
cp wabi.media-node.example.json wabi.media-node.json
```

Set the public SFU endpoint, region/capacity hints, and the Authorities you want
to serve. Every Authority entry needs its own one-time pairing token the first
time it joins.

Validate without making network requests:

```bash
python3 scripts/wabi-media-node.py --config wabi.media-node.json --check
```

## 2. Start the controller

```bash
python3 scripts/wabi-media-node.py --config wabi.media-node.json
```

The controller will:

1. redeem each one-time token independently;
2. persist the returned Authority-specific node id/secret under
   `data/wabi-media-node/pairings.json` with private file permissions where the
   OS supports them;
3. heartbeat outbound to every paired Authority;
4. advertise the same physical SFU/provider/region/capacity to every Authority;
5. claim only `media_relay` jobs;
6. activate the Authority's tenant-scoped room at the configured SFU endpoint;
7. report the job result back using that Authority's own node credential.

After a successful first pairing, remove the consumed `pairingToken` from the
config. The persisted pairing is sufficient on later starts.

## 3. Trust boundary

A shared node intentionally has multiple credentials, but they are independent:

```text
physical Media Node
  pairing A -> Authority A node id + secret
  pairing B -> Authority B node id + secret
  pairing C -> Authority C node id + secret
```

Authority A never receives B or C's secret. A media job targeted to A's assigned
node id cannot be claimed by B's node identity. Room activation also requires the
secret for the exact assigned MediaRelay node.

The Media Node does not receive WabiDB state, chat history or user passwords.
Backend room names are the opaque tenant-scoped names produced by the Authority,
not human channel names.

## 4. Capacity and draining

The config can advertise:

- `maxRooms`;
- `maxParticipants`;
- `maxParticipantsPerRoom`;
- `acceptingNewRooms`;
- region and shared/private mode.

Authorities use these values to avoid selecting a node that explicitly declares
itself full or draining. Current advertised totals are selection constraints, not
yet an atomic global reservation system across Authorities. Until hard shared
quotas land, operators should leave meaningful headroom rather than advertising
100% of physical capacity.

To drain a node, set:

```json
"acceptingNewRooms": false
```

and restart the controller. Existing SFU rooms are not forcibly terminated by
that setting; it only prevents new placement once Authorities receive the updated
advertisement.

## 5. Simple-setup target

This script is the protocol/controller implementation, not the final beginner UX.
The release target remains one operator command that starts the controller,
reference SFU and TURN where needed. The internal topology may contain multiple
processes or containers; normal administrators should not have to configure them
one by one.
